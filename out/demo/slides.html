Contract-Driven Data Quality Monitor

Data contracts become the single source of truth for "good data" — defects are detected automatically, visible, notified to the right owner, and published to the marketplace.

Built by Danilo Personeni with a team of AI agents.

python run.py demo --auto-approve runs the whole flow live.

The value

BeforeWith this product
Quality rules live on paper; owners hear about defects only when a consumer complainsEvery active contract's rules run on schedule against the source — 100% of seeded defects found automatically (28/28, 0 false positives)
Marketplace consumers can't tell if a data product is trustworthyEach product gets a live quality score + status in marketplace.json, plus a dashboard with trends

Architecture — what is an agent (LLM) and what is not

User/Scheduler → Orchestrator (code) → A1 → A2 → A3 → A4 → A5?

LLM agents — only where the task is fuzzyDeterministic code — everywhere correctness is checkable
A1 Contract Architect: drafts the ODCS v3.0.0 YAML from the real schema; schema validation + human approval gate before activeOrchestrator: fixed pipeline, per-contract schedules, no LLM — reproducible & free
A5 Issue Resolver: root-cause + fix suggestion as constrained JSON; human accepts/rejects/closesA2 Quality Executor: contract rules → read-only SQL, runs + history, deduped issues (no LLM can invent a rule)
A3 Metrics / A4 Notify+Marketplace: SQL aggregation → dashboard; recipients read only from the contract; simulated JSON channels

Guardrails are code, not prompts: source DB opened read-only (writes physically fail), recipients only from the contract, source write-back only by the orchestrator in one transaction after human approval.

Capabilities A–E — one line each, with evidence

  • A contracts: 5 ODCS v3.0.0-valid YAML contracts, human-approved → contracts/*.yaml
