Contract-Driven Data Quality Monitor

Turning ODCS data contracts into trusted, visible, actionable data quality — with a team of AI agents.

python run.py demo --auto-approve runs the whole flow.

The problem

  • Data contracts (schema, meaning, owner, SLA, quality rules) mostly live on paper
  • Owners learn about defects only when a consumer complains
  • Marketplace consumers can't see whether a data product is trustworthy right now

Architecture — deterministic orchestrator, 5 agents, LLM only where fuzzy

  • Orchestrator: plain Python pipeline + per-contract schedules (no LLM — reproducible, cheap, guardrails in code)
  • A1 Contract Architect (LLM): drafts ODCS v3.0.0 contract → schema-validated → human approves → active
  • A2 Quality Executor (no LLM): contract rules → read-only SQL, runs + history, deduped issues
  • A3 Metrics / A4 Notify & Marketplace (no LLM): dashboard, owner/steward mails from the contract, marketplace score
  • A5 Issue Resolver (LLM): root-cause suggestion → human accepts/rejects → write-back only by orchestrator, one transaction, then re-verify

Capability A — contracts (ODCS v3.0.0, human-approved)

  • 5 contracts in contracts/*.yaml, validated against the official ODCS v3.0.0 JSON schema
  • 28 quality rules; owner + steward + SLA schedule in every contract
  • editing an approved contract → back to draft (re-approval); live: run.py draft --table customers

Capabilities B–D — checks, dashboard, notify + marketplace

  • run.py tick: every due contract runs its rules (read-only source), results stored with history
  • out/dashboard.html: per contract/table/rule/dimension/severity + trend over last runs + score
  • out/notifications/*.json: actionable issue to owner+steward from the contract; out/marketplace.json: score/status per product

Detection report (vs our own seeded defect manifest)

100% — 28/28 found, 0 missed, 0 false positives

  • 28 deliberately seeded defects / 36 rows across 7 dimensions (data/defect_manifest.csv)
  • out/detection_report.xlsx (Excel tab) + run.py report

Capability E — resolve with human in the loop

  • run.py resolve --issue N: A5 proposes root cause + fix (read-only tools, structured JSON)
  • HITL gate: accept / reject / close — recorded in the DB
  • accepted write-back: orchestrator executes one transaction, contract re-runs, rule confirmed PASS

Measured results & disclosure

  • pipeline: 1.04 s for 5 contracts / 28 rules; steady-state scheduled run = $0 LLM; one A1 draft ≈ $0.0016 (8,029 tokens)
  • KPIs: 100% detection, 5/5 contracts active; scale analysis for 500 contracts / 50 sources in the DDR
  • code written with Mistral Vibe; runtime LLM = Mistral API (mistral-small-latest) in A1/A5 only — full disclosure in README/DDR
